# InEarth4 회고와 개선 방향

## 유지할 설계 판단

- 실제 휴대전화 조작 경험을 게임의 스킬 규칙으로 변환한 점
- 입력 순서, 시각적 피드백, 자원 소비와 스킬 활성화를 하나의 흐름으로 완성한 점
- 스킬 패턴과 비용을 `ScriptableObject` 데이터로 구성한 점
- 반복 생성되는 투사체와 UI 객체를 비활성화 후 재사용한 점

## 현재 다시 구현한다면 개선할 부분

### 패턴 식별 형식 개선

현재는 노드 번호를 구분자 없이 연결한 문자열을 사용합니다. 0부터 8까지의 한 자리 번호에서는 동작하지만 노드 수가 늘어나면 서로 다른 경로가 같은 문자열이 될 수 있습니다. 현재라면 정수 배열을 직접 비교하거나 구분자가 포함된 불변 키를 사용합니다.

### 입력 판정 로직 분리

현재 패턴 입력, 전투, 적 관리, UI가 `PlayManager`에 함께 있습니다. 현재라면 패턴 판정을 Unity 입력 코드와 분리해 다음과 같이 구성합니다.

- `PatternInputController`: 포인터와 노드 입력 수집
- `PatternMatcher`: 입력 순서와 스킬 패턴 비교
- `SkillService`: 마나와 중복 사용 검사
- `PatternPresenter`: 연결선과 입력 상태 표시

`PatternMatcher`를 일반 C# 클래스로 만들면 Unity 실행 없이도 올바른 패턴, 잘못된 패턴, 중복 노드와 빈 입력을 단위 테스트할 수 있습니다.

### 공통 객체 풀 도입 검토

투사체, 이펙트, 골드와 UI마다 재사용 코드가 별도로 존재합니다. 현재라면 생성·대여·반납 규칙을 공통화할 수 있는 객체 풀을 검토하되, 객체마다 초기화 방식이 다르므로 무조건 하나의 구현으로 합치지는 않습니다.

### 명명과 접근 범위 정리

오타가 포함된 이름과 외부에 공개된 실행 상태 필드가 있습니다. 전체 Unity 참조를 확인할 수 있는 환경에서 이름을 수정하고, 에디터 설정값은 `[SerializeField] private`, 내부 실행 상태는 `private`으로 구분합니다.
